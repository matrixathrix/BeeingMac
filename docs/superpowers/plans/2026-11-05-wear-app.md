# Beeing for Wear OS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The watch app (rate + tag + save offline for 2+ days, its own reminders, ring-closed celebration, Tile, three complications) and the Data Layer sync between it and the phone.

**Architecture:** `:wear` is a thin Android shell over `:shared`: every rule it applies (waiting hours, streak numbers, delivery, top tags, merge) is a pure function in `:shared` with JVM tests. Sync is `DataClient` only: the watch writes one DataItem per save, and the phone answers with one replaced `/state` item. Every watch surface redraws through one `WatchSurfaces.refresh(context)` call, fired on four events only.

**Tech Stack:** Kotlin 2.2.10, AGP 9.1.1, Wear Compose Material 3, ProtoLayout Tiles, `androidx.wear.watchface:watchface-complications-data-source`, `com.google.android.gms:play-services-wearable`, `kotlinx-serialization-json` (plugin version = kotlin). Library versions are the builder's call: the latest stable that is at least two weeks old.

**Spec:** `docs/superpowers/specs/2026-11-05-wear-companion-design.md`. **Requires** `docs/superpowers/plans/2026-11-05-wear-groundwork.md` to be done first (`:shared`, `ReplayCarry`, `mergeIncoming`, `Origin`, tombstones, the v2 channels).

## Global Constraints

- `:wear` `applicationId = "com.example.beeing"`, `minSdk = 30`, signed with the same key as `:app` (debug: the same debug keystore; release: `~/.android-keystores/beeing-release.properties`).
- `<meta-data android:name="com.google.android.wearable.standalone" android:value="true"/>`.
- No polling: complication `UPDATE_PERIOD_SECONDS = 0`; Tile `freshnessIntervalMillis = 0`; no `WorkManager` periodic work; no foreground service; no sensor listeners.
- Surfaces refresh only on: a watch save, a `/state` arrival, the hourly alarm, boot.
- Watch copy (exact): notification "How was 2pm – 3pm?" / "2 hours waiting", actions "Rate" / "Later"; score resting "Pick a rating", button "Next"; tags "More", "Save · N tags" ("Save · 1 tag"); "Saved"; "1 more"; "That hour just closed"; ring "Day complete" / "Beginner day complete" / "Yesterday's ring closed" / "Super day"; caught up "All caught up"; unsynced "Open Beeing on your phone to set up"; chime tip "Beeing already marks every hour. If Galaxy's hourly chime is on, you'll feel both — you can turn it off under Sounds and vibration."
- Phone copy (exact): Silent hours sheet "Beeing on your watch keeps the same silent hours. Changes reach your watch the next time it connects to your phone."; Pause sheet "Your watch pauses too. If it isn't connected right now, the pause starts as soon as it reconnects."
- Time format "2pm – 3pm" everywhere (reuse the phone's formatter, moved to `:shared` if needed).
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Watch never synced** — no `/state` stored: no reminders are posted, launcher/Tile/complications show "Open Beeing on your phone to set up", and Save is unreachable. → test in Task 1 (`watchView` with null state).
2. **Offline across two midnights** — the watch's streak number after resuming over 3 local days equals what the phone computes after sync. → test in Task 1.
3. **Hour expires mid-rating** — the flow hands score and tags to the newer waiting hour, or closes with "That hour just closed" when none is waiting. → test in Task 6 (`RatingFlow`).
4. **Phone gets the same watch rating twice** (DataItem redelivered) — merge is idempotent: no duplicate entry, no second refund. → test in Task 3.
5. **Watch charging while connected** — the phone rings; unplugged — the phone posts silently. → test in Task 4 (`phoneDelivery`).
